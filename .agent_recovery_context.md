## 3) Facts that are easy to get wrong
*Seeded from planning. Add each fact here as soon as it causes a wrong answer.*
- The spec's heading says "Node.js" but its body says "Node.js / Flask". We
  use Node and don't add Python.
- In the DB, `page_url` holds the **normalized** URL. The browser's full URL
  is `raw_url`. Don't swap them.
- The tracker sends `text/plain`. If `POST /api/events` only has
  `express.json()`, `req.body` comes back empty without an error. That route
  also needs `express.text()` plus `JSON.parse`.
- The heatmap iframe loads the demo page, and the demo page loads the tracker.
  Without the `cf_preview` / in-iframe guard, each heatmap view records fake
  page views.
- `helmet`'s defaults break this app three ways; `app.js` overrides each:
  `X-Frame-Options: SAMEORIGIN` blocks the dashboard iframe (use CSP
  `frame-ancestors`), `Cross-Origin-Resource-Policy: same-origin` blocks other
  sites from loading `/tracker.js`, and `upgrade-insecure-requests` makes
  Safari fetch `http://localhost` over https (kept in production only).
- In helmet 8 the X-Frame-Options option is `xFrameOptions`, not `frameguard`.
- `crypto.randomUUID` only exists in secure contexts. `http://localhost`
  counts as secure; a plain-http LAN IP doesn't. Keep the fallback.
- `NEXT_PUBLIC_API_URL` is inlined at build time, so changing it on Vercel
  needs a redeploy.
- Render's free tier sleeps, so the first request after idle takes 30–50s.
  That's expected, not a bug.
- `/demo/index.html`, `/demo/` and `/demo` must all normalize to the same
  `page_url`.
- The root `seed` script ends in `--` (`npm -w server run seed --`). Without
  it, `npm run seed -- --reset` hands `--reset` to npm as a config flag and
  the seed script never sees it.
- `create-next-app` refuses a target folder containing files outside its
  small allowlist (`.gitignore`, `LICENSE`, `docs`, …). Scaffold `dashboard/`
  first, then add `dashboard/.env.local.example`.
- `concurrently@10` requires Node ≥ 22 and `vitest@5` requires ≥ 22.12;
  that's why `engines` says `>=22.12`.
- mongodb-memory-server's binary lives in `<root>/node_modules/.cache/mongodb-memory-server`
  (downloaded by `npm install`). Run it via npm scripts. A plain `node` run
  from `server/` re-downloads 148 MB into `~/.cache/mongodb-binaries`,
  outside the repo; for ad-hoc scripts set
  `MONGOMS_DOWNLOAD_DIR=<root>/node_modules/.cache/mongodb-memory-server`.
- happy-dom 21 disables JavaScript evaluation by default
  (`settings.enableJavaScriptEvaluation: true`). Scripts run in a `vm`
  context whose global is the window, so a test can stub `win.setTimeout`,
  `win.navigator.sendBeacon` or `win.fetch` before or after loading the
  tracker. A click on an `<a href="/path">` makes happy-dom navigate; test
  links use `#hash` hrefs.
- jsdom 30 needs Node ≥ 22.22.2; this Mac has 22.14. That's one reason the
  tracker tests use happy-dom.
- Root scripts that take arguments end in `--` (`test`, `seed`); without it
  npm swallows flags like `--project` or `--reset` as its own config.
- The Mac is Apple Silicon (arm64), but Homebrew at `/usr/local` is the
  **Intel copy running under Rosetta**. `brew install --cask` would fetch
  Intel builds of apps such as OrbStack or Docker Desktop. Install those
  from the vendor's Apple Silicon download instead.
- Mongoose `insertMany(docs, { ordered: false })` **silently skips** docs
  that fail schema validation. `events.js` passes `throwOnValidationError: true`
  so a validator/schema mismatch fails loudly instead of under-counting.
- Express 5: `req.body` is `undefined` (not `{}`) when no parser matched, and a
  repeated query param (`?page=a&page=b`) arrives as an array. Check types
  before using either.
- Mongoose builds indexes automatically on connect unless `autoIndex: false`.
  The Event schema turns it off; `index.js` and `test/setup.js` call
  `Event.createIndexes()` themselves. Don't use `syncIndexes()`: it drops
  indexes that aren't in the schema.

## 4) Reference Decisions (append-only)

| Date | Decision | Why |
|---|---|---|
| 2026-10-12 | Backend: Node 20+, Express, ESM JavaScript (no TS build step) | Matches the spec heading; one language; simpler deploy |
| 2026-10-12 | DB access via Mongoose | Schema, validation and indexes declared in one place |
| 2026-10-12 | Dashboard: Next.js App Router, TypeScript, Tailwind, SWR polling every 5s | Spec allows React/Next; polling makes the demo feel live without websockets |
| 2026-10-12 | Tracker: zero-dep IIFE, served from `server/public/` with the demo pages | One deploy serves API + tracker + demo; no copy step |
| 2026-10-12 | Single `events` collection; sessions aggregated on read | Enough at assignment scale; a `sessions` collection is the documented scale-up path |
| 2026-10-12 | Session = localStorage id, 30-min inactivity timeout | A localStorage id with no expiry would make one session per browser forever |
| 2026-10-12 | `page_url` = normalized `origin + pathname`; `raw_url` kept | UTM/hash/trailing-slash variants would split heatmaps |
| 2026-10-12 | Clicks: `pageX/pageY` + viewport + doc size; server-derived `device` bucket; heatmap x as % of `doc_w` | Raw coordinates aren't comparable across screen sizes |
| 2026-10-12 | Client `timestamp` + server `received_at` | Client clocks can be skewed |
| 2026-10-12 | Send via `sendBeacon` (text/plain) with `fetch` keepalive fallback | Clicks on links navigate away before a normal fetch completes; text/plain avoids preflight |
| 2026-10-12 | CORS: open on ingest, `DASHBOARD_ORIGIN` only on reads | Tracker runs on any site; analytics reads shouldn't be public |
| 2026-10-12 | Tests: Vitest + supertest + mongodb-memory-server | Real Mongo queries with no running DB |
| 2026-10-12 | Hosting: Atlas M0, Render (server), Vercel (dashboard) | All free tiers |
| 2026-10-12 | Node floor raised to **22+** (`engines: ">=22"`); supersedes "Node 20+" above | `concurrently@10` needs Node 22; Node 20 reached EOL on 2026-04-30 |
