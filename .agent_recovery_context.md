## 3) Facts that are easy to get wrong
*Seeded from planning. Add each fact here as soon as it causes a wrong answer.*
- The spec's heading says "Node.js" but its body says "Node.js / Flask". We
  use Node and don't add Python.
- The spec doesn't list a pages endpoint, but "Select a page URL" in the
  Heatmap View needs `GET /api/pages`.
- In the DB, `page_url` holds the **normalized** URL. The browser's full URL
  is `raw_url`. Don't swap them.
- The tracker sends `text/plain`. If `POST /api/events` only has
  `express.json()`, `req.body` comes back empty without an error. That route
  also needs `express.text()` plus `JSON.parse`.
- The heatmap iframe loads the demo page, and the demo page loads the tracker.
  Without the `cf_preview` / in-iframe guard, each heatmap view records fake
  page views.
- `helmet`'s default `X-Frame-Options: SAMEORIGIN` stops the dashboard from
  showing demo pages in an iframe.
- `crypto.randomUUID` only exists in secure contexts. `http://localhost`
  counts as secure; a plain-http LAN IP doesn't. Keep the fallback.
- `NEXT_PUBLIC_API_URL` is inlined at build time, so changing it on Vercel
  needs a redeploy.
- Render's free tier sleeps, so the first request after idle takes 30–50s.
  That's expected, not a bug.
- `/demo/index.html`, `/demo/` and `/demo` must all normalize to the same
  `page_url`.

## 4) Reference Decisions (append-only)

| Date | Decision | Why |
|---|---|---|
| 2026-10-12 | Backend: Node 20+, Express, ESM JavaScript (no TS build step) | Matches the spec heading; one language; simpler deploy |
| 2026-10-12 | DB access via Mongoose | Schema, validation and indexes declared in one place |
| 2026-10-12 | Dashboard: Next.js App Router, TypeScript, Tailwind, SWR polling every 5s | Spec allows React/Next; polling makes the demo feel live without websockets |
| 2026-10-12 | Tracker: zero-dep IIFE, served from `server/public/` with the demo pages | One deploy serves API + tracker + demo; no copy step |
| 2026-10-12 | Single `events` collection; sessions aggregated on read | Enough at assignment scale; a `sessions` collection is the documented scale-up path |
| 2026-10-12 | Session = localStorage id, 30-min inactivity timeout | A localStorage id with no expiry would make one session per browser forever |
| 2026-10-12 | `page_url` = normalized `origin + pathname`; `raw_url` kept | UTM/hash/trailing-slash variants would split heatmaps |
| 2026-10-12 | Clicks: `pageX/pageY` + viewport + doc size; server-derived `device` bucket; heatmap x as % of `doc_w` | Raw coordinates aren't comparable across screen sizes |
| 2026-10-12 | Client `timestamp` + server `received_at` | Client clocks can be skewed |
| 2026-10-12 | Send via `sendBeacon` (text/plain) with `fetch` keepalive fallback | Clicks on links navigate away before a normal fetch completes; text/plain avoids preflight |
| 2026-10-12 | CORS: open on ingest, `DASHBOARD_ORIGIN` only on reads | Tracker runs on any site; analytics reads shouldn't be public |
| 2026-10-12 | Tests: Vitest + supertest + mongodb-memory-server | Real Mongo queries with no running DB |
| 2026-10-12 | Hosting: Atlas M0, Render (server), Vercel (dashboard) | All free tiers |
