## 3) Facts that are easy to get wrong
*Seeded from planning. Add each fact here as soon as it causes a wrong answer.*
- The spec's heading says "Node.js" but its body says "Node.js / Flask". We
  use Node and don't add Python.
- In the DB, `page_url` holds the **normalized** URL. The browser's full URL
  is `raw_url`. Don't swap them.
- The tracker sends `text/plain`. If `POST /api/events` only has
  `express.json()`, `req.body` comes back empty without an error. That route
  also needs `express.text()` plus `JSON.parse`.
- The heatmap iframe loads the demo page, and the demo page loads the tracker.
  Without the `cf_preview` / in-iframe guard, each heatmap view records fake
  page views.
- `helmet`'s defaults break this app three ways; `app.js` overrides each:
  `X-Frame-Options: SAMEORIGIN` blocks the dashboard iframe (use CSP
  `frame-ancestors`), `Cross-Origin-Resource-Policy: same-origin` blocks other
  sites from loading `/tracker.js`, and `upgrade-insecure-requests` makes
  Safari fetch `http://localhost` over https (kept in production only).
- In helmet 8 the X-Frame-Options option is `xFrameOptions`, not `frameguard`.
- `crypto.randomUUID` only exists in secure contexts. `http://localhost`
  counts as secure; a plain-http LAN IP doesn't. Keep the fallback.
- `NEXT_PUBLIC_API_URL` is inlined at build time, so changing it on Vercel
  needs a redeploy.
- Render's free tier sleeps, so the first request after idle takes 30–50s.
  That's expected, not a bug.
- `/demo/index.html`, `/demo/` and `/demo` must all normalize to the same
  `page_url`.
- The root `seed` script ends in `--` (`npm -w server run seed --`). Without
  it, `npm run seed -- --reset` hands `--reset` to npm as a config flag and
  the seed script never sees it.
- `concurrently@10` requires Node ≥ 22 and `vitest@5` requires ≥ 22.12;
  that's why `engines` says `>=22.12`.
- mongodb-memory-server's binary lives in `<root>/node_modules/.cache/mongodb-memory-server`
  (downloaded by `npm install`). Run it via npm scripts. A plain `node` run
  from `server/` re-downloads 148 MB into `~/.cache/mongodb-binaries`,
  outside the repo; for ad-hoc scripts set
  `MONGOMS_DOWNLOAD_DIR=<root>/node_modules/.cache/mongodb-memory-server`.
- happy-dom 21 disables JavaScript evaluation by default
  (`settings.enableJavaScriptEvaluation: true`). Scripts run in a `vm`
  context whose global is the window, so a test can stub `win.setTimeout`,
  `win.navigator.sendBeacon` or `win.fetch` before or after loading the
  tracker. A click on an `<a href="/path">` makes happy-dom navigate; test
  links use `#hash` hrefs.
- jsdom 30 needs Node ≥ 22.22.2; this Mac has 22.14. That's one reason the
  tracker tests use happy-dom.
- Root scripts that take arguments end in `--` (`test`, `seed`); without it
  npm swallows flags like `--project` or `--reset` as its own config.
- The Mac is Apple Silicon (arm64), but Homebrew at `/usr/local` is the
  **Intel copy running under Rosetta**. `brew install --cask` would fetch
  Intel builds of apps such as OrbStack or Docker Desktop. Install those
  from the vendor's Apple Silicon download instead.
- Mongoose `insertMany(docs, { ordered: false })` **silently skips** docs
  that fail schema validation. `events.js` passes `throwOnValidationError: true`
  so a validator/schema mismatch fails loudly instead of under-counting.
- Express 5: `req.body` is `undefined` (not `{}`) when no parser matched, and a
  repeated query param (`?page=a&page=b`) arrives as an array. Check types
  before using either.
- Mongoose builds indexes automatically on connect unless `autoIndex: false`.
  The Event schema turns it off; `index.js` and `test/setup.js` call
  `Event.createIndexes()` themselves. Don't use `syncIndexes()`: it drops
  indexes that aren't in the schema.
- Headless Brave on desktop draws a classic 15 px scrollbar: at 1280 px the
  page measures 1265 wide. Measure layouts with `--hide-scrollbars`, as the
  seed's `LAYOUT` was, so `doc_w` equals the viewport width the way it
  does on macOS, on phones and in the heatmap iframe.
- The seed's `LAYOUT` table is a snapshot of the demo pages. If their markup
  or `demo.css` changes, re-measure with `scratch/measure-layout.mjs`
  (git-ignored; needs the API running). `seed.test.js` checks that clicks
  land inside the table's boxes, not that the boxes still match the pages.
- `seed.js` imports `config.js` inside `main()` on purpose: `config.js`
  throws without `MONGODB_URI`, and the tests don't set it.
- The root `npm test` runs only the **server** suites. Dashboard tests are
  `npm -w dashboard test`. A green `npm test` says nothing about the dashboard.
- `next dev` writes `dashboard/AGENTS.md` when it detects a coding agent,
  even though the scaffold was told `--no-agents-md`. `agentRules: false` in
  `next.config.ts` stops it; don't remove that line. Version-matched Next 16
  docs are in `node_modules/next/dist/docs/`.
- The scaffold's `dashboard/.gitignore` ignores `.env*`; the `!.env*.example`
  line is what keeps `.env.local.example` in git.
- `tsc --noEmit` alone fails in `dashboard/` until `next typegen` (or a
  build) has generated `.next/types`; the `typecheck` script runs both.
- Tailwind 4 is wired through `@tailwindcss/turbopack` in `next.config.ts`,
  with no PostCSS config. `next build --webpack` would build without styles.
- CDP full-page screenshots (`captureBeyondViewport: true`) leave the
  cross-origin heatmap iframe **blank**, which looks like a broken heatmap.
  Use `FULL=0` with a tall viewport. The iframe's own logs live on its own
  CDP target (`scratch/iframe-debug.mjs`). In a `sandbox=""` document,
  `location.origin` still shows the URL's origin; `self.origin` is `"null"`.
- Heatmap `y` is not scaled by **width**. The TODO's original formula did
  that, and it put the About CTA 273 px off at 1440; don't bring it back.
  Desktop `x` is centre-anchored and tablet/mobile `x` is proportional
  (Phase 4 D1, `dashboard/src/lib/heatmap.ts`). Phone/tablet `y` **is**
  scaled by **document height** (`refHeight / doc_h`, 2026-10-14); desktop
  `y` stays raw.
- `doc_h` is `scrollHeight`: on a page shorter than the window it is the
  **window's** height, not the page's (seeded tablet Home: 1024 in a
  768×1024 window). The heatmap only trusts `doc_h` when
  `doc_h > viewport_h`; that's why `GET /api/heatmap` returns `viewport_h`.
- SWR doesn't poll a hidden tab (`refreshWhenHidden` is off). A headless check
  that opens a second tab must give the visitor its own window
  (`Target.createTarget({ newWindow: true })`) and keep the dashboard focused
  (`Emulation.setFocusEmulationEnabled`), or the "live" update never comes.
- Clicks dispatched over CDP are stored up to ~0.9 px off the dispatched
  point (browser rounding). Compare heatmap dots with the **stored** x/y,
  never with the point the script clicked.
- A clone of this repo in a folder with another name is a different Compose
  project: `docker compose up -d` there starts a second `mongo` and fails
  on :27017. Set `COMPOSE_PROJECT_NAME=causalfunnel` to reuse the running
  container. A second `next dev` can't share :3000 either (Next moves to
  3001, and CORS then refuses it), so a side-by-side check needs its own
  `PORT`, `DASHBOARD_ORIGIN` and `NEXT_PUBLIC_API_URL`.
- Behind Render, `X-Forwarded-For` keeps what the client sent and appends
  the real address plus two proxy hops, so neither its leftmost entry nor a
  guessed `trust proxy` count is a safe client key. The rate limit keys on
  `True-Client-IP`, which Render's edge overwrites, only when
  `CLIENT_IP_HEADER=true-client-ip` is set (Render only); otherwise `req.ip`.
  Source: Render staff demo `johnbeynon/header-test`, not Render's docs.
- Render asks for a card before creating a Blueprint; a manual free Web Service
  with the `render.yaml` settings doesn't.
- Pushing over HTTPS fails here: the keychain helper has no GitHub
  credentials and the agent can't prompt. SSH works (key for `prakhar23381`):
  `git push git@github.com:prakhar23381/UserAnalyticsApplication.git main`.
  `origin` stays HTTPS, which is fine for fetching the public repo.
- With `keepPreviousData`, SWR returns the previous key's data while the new
  key loads. Views that use it (sessions list, heatmap) render from the
  response's own fields (`data.page`, `data.page_url`, `data.device`), never
  from the URL. The journey doesn't use it.
